# Task Breakdown

**What it is** — the design broken into vertical slices: the **task list**, and the **handoff contract** to the shippers — `/queue:ship-task` reads these fields to implement a **single** slice e2e; `/queue:ship-queue --integration-branch` reads the **same** fields (notably `depends-on`) to drain the **whole** breakdown in dependency order. The whiteboard's "Task Breakdown." This file is the **contract** (the columns + the review hooks); the rigorous, grounded **builder** that fills it after the RFC passes review is `/plan:task-breakdown` (the writing skill drafts a first cut; `/plan:task-breakdown` hardens it — verifying every edge and touch-point against the code).
**Applies when** — every feature RFC. Non-slice work (perf / migration / refactor / infra) lists its proof differently (below), it isn't forced into slices.

## Claude drafts (derivable)
- A proposed set of vertical slices + a demoable proof for each, from the design above.

## Author decides (grill — printed question + your recommendation + "or your take")
- **Slice only on a deep-enough LLD.** Slices drafted before §6 nails its mechanisms are speculative and over-granular. If the LLD still carries undecided mechanism forks, resolve those first, *then* slice — and prefer **consolidation** over many thin slices.
- **Slice boundaries** — each slice is a unit of behaviour change that crosses a layer boundary and can be asserted in isolation.
- **HITL/AFK tag** — where does a human *decision* sit? An autonomous slice runs the gates with no pause; a human-gated slice has one explicit decision. Human-overridable.

  **Write one of exactly two canonical values: `human-gated` or `autonomous`.** This is the single home for the tag's vocabulary — `/queue:ship-task`, `/queue:ship-queue` and the reviewer all resolve against the rule below, and none of them keeps its own copy.

  **Resolution is longest-prefix match against the token table**, not a split on punctuation — several tokens contain a hyphen, so any rule that cuts at `-` would truncate `human-gated` to `human` and match nothing. Strip markdown emphasis (`**`, `*`, backticks) and leading whitespace, then take the **longest** table entry the cell starts with, case-insensitively; whatever follows is annotation and is ignored, whatever its separator. That resolves `**human-gated**`, `human-gated: security`, `human-gated (schema)`, `AFK; source flips stay operator actions`, `AFK — run-time-gated: the operator is the gate` and `autonomous once 5 and 6 are approved` alike, and a new annotation style needs no new rule.

  | Resolves to | Tokens |
  |---|---|
  | **gated** | `human-gated`, `HITL`, `🔒` |
  | **autonomous** | `autonomous`, `AFK`, `run-time-gated`, `⚙` |

  Longest-first matters: `AFK — run-time-gated` starts with `AFK` and resolves autonomous either way, but a cell beginning `run-time-gated` must match that entry rather than any shorter prefix.

  **Resolve the column too, not only the cell.** The header is usually `HITL/AFK`; `HITL`, `HITL / AFK`, `Gate` and `Tag` also name it — match case-insensitively with whitespace collapsed. A Task Breakdown table with **no** resolvable gate column fails closed the same way a bad cell does: treat every row as gated and tell the operator, rather than reading the absence as blanket permission to ship unattended.

  A consumer matching only the canonical pair misses every other spelling. **`run-time-gated` is autonomous, not gated** — the operator running a script later is a run-time gate, not a build-time decision (the three-category rule in `/plan:task-breakdown`'s reference calls it "build AFK"), and reading it as gated would park work nobody asked to review.

  **A cell resolving to neither is read as gated and flagged, never as autonomous** — an unparseable tag must not become a silent licence to ship unattended. Fail-closed is the backstop, not the mechanism: it only protects when the table above is complete, since a missing *autonomous* spelling fails closed into a stalled drain. **Both shippers honour it:** `/queue:ship-task` pauses a human-gated slice at its decision point, and a `/queue:ship-queue` drain reads the same tag at grounding and records a `human-gated` blocker rather than shipping the slice — so the drain does not stall, but it also does not autonomously ship what the author reserved. The tag is therefore load-bearing in an unattended run: an over-gated breakdown parks slices that needed no human, which is precisely what the second pass below is for.
- **The autonomy second pass — re-examine every tag, in both directions.** Tagging once, by feel, produces the `sensitive ⇒ gate` reflex the three-category rule exists to stop, and its mirror: a slice left autonomous because nothing about it *felt* risky. So make a deliberate second pass over the tags before the table is final. Two of its three questions are answerable from the RFC alone and belong here, at draft time; the third needs the codebase and is `/plan:task-breakdown`'s (the worked rule — what counts as a guardrail, and the binding on converting a tag — lives in that skill's `reference.md`; read it there rather than re-deriving it).
  - **What does the human add that the automated gates cannot?** "Someone should look at the diff" is not an answer — the merge gate runs on every slice and `/review:review-panel` on every code slice (its skip-whitelist exempts a docs-only diff), so a gate that only asks for another read of the same diff buys nothing. (The Codex sweep reads it too, but it is post-PR and legitimately comes up absent, so do not lean on it here.) A gate earns its keep by naming a **judgment** those cannot make.
  - **Is the answer already settled in the Decisions Log?** A contract, a name, a default, an ordering the RFC already decided is a **lookup**, not a decision — the slice builds autonomously against the decided answer. If it is genuinely still open, resolving it *now* in the Log is the fix, because the gate belongs on the decision, not on the build. This is where a contract slice usually lands: still in flux, it earns a gate; settled in the Log, it does not.
  - **The pass runs both ways — it is not a push toward zero gates.** Where no approving review is required to merge, the tag is where a human is deliberately pulled in *during* the build rather than a belt over a guaranteed later read. That makes an over-gated breakdown a real cost and an under-gated one a real risk. An autonomous slice whose defect would be **expensive to discover late** and which **no automated gate covers** earns a gate it does not currently have; adding one is as much an output of this pass as removing one.
- **Whole-RFC completion** — the breakdown must cover the *supporting* work too, not just core code: the tests (§8), the observability/dashboards (§7), the flag wiring (§10), the operational jobs (§11), runbooks, and — where §7's output-quality concern applies — the **quality-evaluation harness** (the sample, the rubric or gold set, the runner) that measures the bar, which is build work like any other and not something the eval "just happens" to have. A breakdown that's only the feature code is incomplete. When the RFC **establishes a new pattern others will follow**, the doc that sets the precedent (the `CLAUDE.md`, architecture or data-model doc, or skill update) is itself a slice; so is **correcting a doc this change makes stale** (see Phase 0 step 6). These are slices, not afterthoughts.
- **Two RFC-tail terminal slices close every RFC**, both depending on all the feature slices (an ordering-only *sequencing* edge, like the persona-run slice — kept, not pruned): an **ADR-extraction** slice — the Decisions-Log entries that generalize *beyond this feature* become ADRs via `/plan:adr` (skip only when none generalize, and say so in the slice); and a **harness-education** slice — fold what building this RFC taught into the *agent's own* operating knowledge (`.claude/rules`, the relevant `CLAUDE.md`(s), skill checklists/routers, lint/arch-test discoverability) so the next agent on this surface does not re-derive or hallucinate it. Harness education is **not** the human-facing implementation doc or the ADR (those record the design *for humans*) — it targets what the harness itself *loads* so the agent behaves correctly next time.

Each slice carries these fields (so the shippers — `/queue:ship-task` for one slice, `/queue:ship-queue` for the whole drain — can consume it):

```
| # | slice | layers crossed | demoable proof | HITL/AFK | depends-on | RFC anchor | implementing skill |
```
- **demoable proof is NOT a screen** — for backend it's an integration test through the real path, an operational job's READ mode, a `grpcurl` call, or an ingest-to-table assertion (the ingestion path writes the expected rows). State it per slice. Two proof shapes the builder relies on: a **pure config slice** (generated config code) proves via regenerate-with-no-diff + the typed getters compile + a default-value assertion, and owes no bespoke unit tests for the generated config layer. The carve-out is bound to a checkable condition, not self-classification: it applies only when the slice's diff is confined to generated config files plus the config YAML / field declarations — **any** hand-written Go beyond a generated typed getter (a branch, a derivation, a validator) makes it a logic slice that owes table-driven tests, so the table-driven-test posture is never relaxed for hand-written logic. A terminal **persona-run slice** (for a user-facing feature) proves by exercising the assembled feature end-to-end as the new target persona on a real run, evidence captured in **the slice's own PR** (the integration PR only when the breakdown is drained on an `--integration-branch`) — so the proof holds whether the slice ships via `/queue:ship-task` or a non-integration `/queue:ship-queue` run, where no integration PR exists. An **ADR-extraction slice** proves by the ADR file(s) existing under the `adr_dir` setting (default `docs/adr`) capturing the generalizing Decisions-Log entries and linked back from the RFC (or an explicit "no decision generalizes" note when none do). A **harness-education slice is two-phase**: at breakdown time it carries only a *best-effort prediction* of which harness surfaces this RFC will likely enrich — a hypothesis that scopes the slice, **not** a binding spec; when the slice is **picked** (last, after the feature slices), it **re-grounds from scratch** against the *shipped* diff and the drain's own review history, validating or discarding that prediction. Its proof is the concrete guidance edits (rules / `CLAUDE.md` / skill), each **validated against the shipped code** (no hallucinated file/symbol) and gated through `/review:review-panel` (a guidance change has wide blast radius). Its promotion trigger: any defect **class** the drain's reviews caught more than once across slices **must** graduate to durable enforcement in this slice — a lint/arch-test where mechanically checkable, otherwise a loaded `.claude/rules` / `CLAUDE.md` entry — rather than being left as an ephemeral PR/review comment.
- **RFC anchor** — the section(s) this slice implements (LLD / contract / concern), so the implementer is grounded.
- **depends-on** — the other slice(s) that must land first, written as **slice IDs** (the `#`-column identifiers, e.g. `F1a`, `C2t`) — *not* issue numbers (the table predates any filed issue). This is the **DAG edge `/queue:ship-queue` orders the drain on** (it ships a slice only once its deps are merged onto the integration branch); `/queue:ship-task` reads it to settle stacked-vs-independent for a single slice. When a slice is filed as an issue (up front, or just-in-time by `/queue:ship-queue --from-rfc`), these slice-ID deps are translated to the dep issues' `#N` in the issue's `## Execution` → `Depends-on`; so the table speaks slice IDs and a filed issue speaks `#N`, for the same edges.
- **implementing skill** — the domain build-skill loaded to build this slice (`/queue:ship-task` loads it for a single slice; `/queue:ship-queue`'s grounding subagent routes off it), found by the SKILL.md domain-routing step — the skills available in the session and the repo's own `.claude/skills/` (a concrete, loadable `/skill` — not a prose pointer). Anchors the slice to its build conventions so implementation doesn't drift from the design. It takes one of **three** honest values (these map 1:1 onto the task-brief `Execution.Implementing skill` field): a concrete **`/skill`**; **`none — <reason>`** when no skill owns the surface (e.g. `none — pure refactor, no new surface`, `none — operational job`) so the cell is a checkable claim, not silence; or **`/skill (verify — may be stale)`** when a skill exists but you are unsure it is current — grounding then reads it for orientation but verifies against the live code rather than trusting it. A slice that needs *two* build skills is usually a sign it should be two slices — split it first; if it is genuinely atomic, list both.

**Out of scope here (deliberately):** PR/branch strategy (the implementer's choice at execution — `/queue:ship-task` per slice, or `/queue:ship-queue`'s integration branch for a drain); ticket creation (post-review, one task-brief issue per slice); estimates (live on the post-review tickets). The Task Breakdown is design-time; execution is the shippers'.

Non-slice work proves differently: a perf change → before/after benchmark; a migration → symmetric up+down + regenerated snapshot; a refactor → the existing suite stays green; an infra change → a deploy smoke.

**The grounded-versus-first-cut stamp.** A table in an RFC is one of two very different artifacts — the **first cut** drafted here alongside the design, whose edges are derived from the design rather than checked against the code, or the **hardened** table `/plan:task-breakdown` emits after verifying every edge and touch-point. They look identical, and a wrong edge misorders an autonomous drain, so the difference has to be legible rather than remembered. `/plan:task-breakdown` stamps it in the framing block, in this fixed form so the reviewer has something testable rather than a confident sentence:

```
Ground-verified: <N> depends-on edges + <M> touch-points against <commit-sha>
```

**The absence of that line means first cut**, and this section stamps nothing.

A count alone is not evidence — an agent that skipped the pass can still write one — so the stamp is backed by a **per-edge record** beneath it: one line per `depends-on` edge naming the file and symbol the edge was verified against (`C2t→F1a: internal/orders/dao/foo.go:88 — reads tenant_type`). That record is what a reader can spot-check: the SHA must resolve and be an ancestor of the RFC's branch, `<N>` must match both the table's edge count and the record's line count, and a sampled line must still hold at that SHA. A stamp failing any of these is reported as a first cut rather than taken at its word. The record is also the honest limit of the mechanism: it makes a *careless* stamp detectable and a *fabricated* one expensive, not impossible.

The review is where provenance gets **reported**, because nothing downstream checks it: `/queue:ship-queue` drains whatever table it finds. So the reviewer always states which one it is read — that statement is the whole mechanism, and it costs nothing on a doc that is legitimately still a first cut. It is graded a **WARN** only when the provenance is actually *wrong* for the situation: a stamp that does not check out, or an unstamped table on a breakdown being handed to a drain. Warning every first-cut RFC would fire on all of them and teach the reader to skip the line, which is how a gate stops being read at all.

## Review hooks (what /plan:tech-design-doc-review checks here)
- A feature RFC has a `## Task Breakdown` with vertical slices → absent → NEEDS WORK.
- Each slice is **machine-consumable**: demoable proof (not a screen) + HITL/AFK tag + depends-on + RFC anchor + implementing skill (or a one-line reason it has none) → missing fields, or a skill omitted on a slice whose layers cross a surface that *has* a matching skill (in the session or the repo's `.claude/skills/`) → WARN.
- The breakdown covers **supporting work** (tests/observability/flags/scripts), not just core code → WARN if only core. When the RFC establishes a **new pattern** or makes an existing doc **stale**, the precedent/correction doc is missing as a slice → WARN.
- The breakdown ends with the **two RFC-tail terminal slices** — an ADR-extraction slice (or an explicit "no decision generalizes") and a harness-education slice, each depending on the feature slices → missing → WARN.
- **Every human-gated slice names what the human decides** — a judgment the automated gates cannot make — rather than asking for another read of a diff the merge gate (every slice) and `/review:review-panel` (every code slice) already cover → a gate with no named decision → WARN.
- A slice gated on a question the **Decisions Log already answers** → WARN: it is a lookup, so the slice builds autonomously against the decided answer. A tag the Log records the **author** setting is exempt — human-overridable by contract, so it is not this gate's to grade.
- The breakdown reports **both directions of the second pass** — the gated count with a one-line reason each, *and* every converted slice with the guardrail identity it was converted on → either half absent → WARN. Reporting only the survivors leaves the riskier direction with no artifact. A converted slice whose guardrail is **another slice** carries a `depends-on` edge on it → named but no edge → WARN, because the drain orders on that column and a prose-only guardrail lets the converted slice ship first.
- Where §7's output-quality concern applies, the **quality-evaluation harness** has a slice (or is explicitly folded into a named one) → absent → WARN. An eval that no slice builds is an eval nobody runs.
- **Report the table's provenance either way** — stamped, or first cut with running `/plan:task-breakdown` named as the next step before any drain. Grade it a WARN only on a breakdown actually being handed to a drain; on one still under design review, report *first cut* and move on, since hardening runs after review and warning every RFC for not yet having taken the next step would fire on all of them and teach the reader to skip the line. A stamp whose **SHA does not resolve, is not an ancestor of the RFC's branch, or whose edge count does not match the table** is reported as a first cut → WARN: a false stamp is worse than none, because it converts unknown provenance into "verified" for the operator deciding whether to drain.
- **Every cross-runtime seam §8 names has an owning slice** — the **consuming** slice, since the consumer is the side that breaks. Per-slice demoable proof cannot cover a contract *between* two slices, so a seam assigned to nobody is a seam nothing tests → unowned → WARN (the §8 FAIL gate already covers an unnamed seam; this covers a named one left orphaned).
- **No PR-strategy / ticket / estimate leakage** into the RFC → WARN.
- Non-slice work is not forced into the slice mould (a refactor with fake "slices") → WARN.
- Many thin / speculative slices over an LLD that still has undecided mechanisms (sliced before the design was deep enough) → WARN.
